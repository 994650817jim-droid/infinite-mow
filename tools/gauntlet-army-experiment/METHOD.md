# 军团战损与标准天门实验

## 取数

历史对账读取同一工作区的原始张飞标准通关记录。每阵从进入割草起，算到下一阵开始或本局结算，覆盖斩将后的补员和残敌。阶段战损由累计阵亡数相减。每次付款按钱币余额差记账，每批三人。历史文件不含士兵生命标识和逐击事件。

新增自然样本从空白局内存档出发，仅设置正式可选主将的上次选择。名册通过原有抽取函数和记录的种子生成。驱动沿用仓库内 `tools/test-gauntlet-natural-standard.mjs` 的八向走位、选卡、招兵、用药及星图操作。张飞优先本命与力量，赵云优先移动与敏捷，另有统御策略可复测。决策依赖场上位置并由脚本操作，不代表真人水平。

测试使用本机 Chrome 软件 Canvas。保留原生游戏更新、受击顿帧、牌面、相机和战斗时钟，开战后跳过世界画面的实际绘制。每位将领的命令按阵轮换，两人的奇偶顺序相反。程序只在军令控件开放时切换。首阵专用性能测量需要独占时，采样进程支持停掉 Phaser 主循环并记录暂停回执。

Vite 只针对测量浏览器返回带观察点的军团模块。每个单位使用对象编号与生命编号组合区分，箭离弦后仍归属于发射时的那一条生命。每次对敌直接命中记录目标实际失去的体力，超杀截在零血。敌方护盾损耗另计。减伤、兵种护甲、自身护盾和首领保命下限均在入伤前生效，入伤按受击前后体力差计算。军团与副将伤害分开。其他单位连带触发的额外伤害没有计入士兵本次直接命中。

出生时登记兵种和本次付款，每个事件保留阵数、阶段、战斗秒与军令。死亡记录实际最后一击。首领近身横扫按触发位置单独识别，避免将不走正面格挡的横扫混入首领技能。普通兵按接触者种类识别，场景投射物与补给伤害也分别归类。未能识别来源的普通伤害保留原分类。存活的士兵在结算时右删失，寿命中位数用 Kaplan–Meier 估计。军令输出与死亡率用各军令的累计存活人秒校正。一个士兵经历两种军令时，两段存活时间分别记账。

## 天门 A/B

过第十五阵时，记录正式晋级按钮前的角色等级、体力、全套星图与构筑、装备、坐骑、本命、副将、全体士兵生命、出牌状态、钱币与神将名册。五阵实验用同一快照重建 A/B 两臂，清空场景中残存的普通敌人和临时攻击物，重置单位战斗动作；两臂共同使用这个条件。完整自然局继续使用自己的战场，其通关结果单列。

A 直接通过正式天门晋级。B 过门时额外使用一次原生选奖面板。武器选项沿用正式出牌的等级、分支与超限条件，调用现有 `weaponUpgrade` 或 `overOption`；将星取自当前合法牌池，额外三个援军取本阵正常兵种与训练等级，实验授予时零花费。已满级或没有合法候选的选项被移除。每次实际选择后检验星图、本命或援军人数确实变化。正常招兵仍按阵数扣钱，两臂的常规抽兵和出卡使用按阵、购买或抽卡序号配对的随机流。

同阵之间仍有实时帧序、出生位置和自动走位分歧。样本用于比较具体构筑的受益与机会成本。完整路线抵达率仅统计自然启动的独立对局。已携带同一天门快照的重复天界实验不增加抵达率分母。

## 重跑

先启动游戏仓库的本机 Vite 开发服。在证据目录执行下列命令，替换游戏仓库路径。每次使用新的输出子目录保留旧证据。

```powershell
node history.mjs
node run.mjs "<游戏仓库>" zhangfei 177 weapon alternate zhangfei-177-new
node run.mjs "<游戏仓库>" zhaoyun 63951 agility reverse zhaoyun-63951-new
node run.mjs "<游戏仓库>" zhangfei 177 weapon guard gate-A-new http://127.0.0.1:5286 0 ./zhangfei-177-new/gate.json A
node run.mjs "<游戏仓库>" zhangfei 177 weapon guard gate-B-new http://127.0.0.1:5286 0 ./zhangfei-177-new/gate.json star
node analyze.mjs
```

各组的 `route.json` 含正常选牌及战斗状态，`army.json` 含全部新兵与命中，`progress.json` 含配置与终态，`summary.json` 为统计。配对组另有 `entry.json`、`reward.json`，可核对两臂干预前构筑，以及各项赠予后的变化。
